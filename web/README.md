# FloodSight · Douala

Bilingual (FR/EN) React front end for **FloodSight** — NISAR radar flood detection and
persistent-hotspot mapping for Douala, Cameroon. Built for the NASA Space Apps Challenge 2026
by Lions Roar Labs.

Radar sees through monsoon cloud and at night, which is why NISAR works in Douala in
June–October. FloodSight shows **where, when and how much water was observed on land** on each
pass. It is a detection and screening tool, **not a forecast**.

---

## Run it

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # typecheck + production build into dist/
npm run preview    # serve dist/ on http://localhost:4173
```

Requirements: Node 18+ (developed on Node 22), and `python3` + Pillow only if you want to
regenerate the placeholder rasters (`npm run data`).

## Pages

| Route | What it does |
| --- | --- |
| `/` | Map dashboard: pass timeline, flood extent, permanent water, hotspots, layer opacity, per-pass metrics |
| `/compare` | Before/after slider over a dry pass and a flood peak, net change, expansion %, presets, AI briefing |
| `/hotspots` | Recurrence ranking, district filter, frequency raster, per-hotspot cause and CSV export |
| `/stats` | Flooded area vs rainfall, threshold chart, full pass table, validation status, detection parameters |
| `/about` | Purpose, 5-step method, the complete "limits" list, credits, honesty rule |

## Data contract

Everything the UI shows is read from `public/data/`. Replace these files with the
`web_v2/` export from notebook 02 — **keep the names and shapes** and the app needs no code
change.

```

  bounds.json                 # [[south, west], [north, east]]
```

### Placeholder data — read this

`public/data/` currently contains **sample data**, generated by
`tools/make_sample_data.py` (deterministic, seeded):

- 11 passes, 18 Jun → 28 Oct 2026, track 58 / frame 4 / ascending, with the real 24-day gap
  between 24 Jul and 17 Aug.
- `flooded_km2` sampled inside the range notebook 02 actually reported, **0.04–0.29 km²**
  (peaks 30 Jun and 28 Oct at 0.29 km², mean 0.153 km²).
- `urban_signal_km2 = 0` everywhere, because ESA WorldCover is not loaded yet. The UI says
  "not a result" instead of showing a fake street layer.
- Raster PNGs are plausible blobs in the right places, not measurements.

`meta.data_status` is `"sample"`, so a banner appears on every page. Setting it to `"final"`
after dropping in the real export removes the banner — no other change needed.

## Honesty rules baked into the UI

- No figure is hard-coded in a component; every number, label and limit comes from
  `stats.json`.
- Missing layers and unfinished validation are shown as **pending**, never as a zero score.
- Flooded streets (`urban_signal_*`) are visually separated from open-water flood, and the
  copy states that the zeros are not a result.
- The compare page measures change **between two satellite passes**, not between a pass and
  the day before.
- The AI assistant answers only from tool results over `stats.json`; when unreachable, the UI
  falls back to a deterministic answer engine using the same numbers.

## Assistant

`api/ask.ts` is a Vercel Node function that calls Gemini Flash with five function
declarations: `list_dates`, `get_flood_stats`, `compare_dates`, `get_neighborhoods`,
`get_limits`. Tool execution happens server-side against `public/data/stats.json`, so the model
never sees raw JSON keys and cannot invent figures.

```bash
cp .env.example .env.local   # then set GEMINI_API_KEY
```

Without a key the function returns `501` and the client transparently uses
`localAnswer()` from `src/lib/assistant.ts` (keyword + date detection, bilingual). Keys are
never committed: `.env*` is ignored apart from `.env.example`.

## Deploy (Vercel, free tier)

Set the project's **Root Directory** to `web`, then add `GEMINI_API_KEY` in
Settings → Environment Variables (`GEMINI_MODEL` optional). `vercel.json` builds `dist/`,
keeps `/data/*` and `/api/*` on the filesystem/function, and rewrites every other deep link
to `index.html` so `/compare`, `/stats`, … survive a reload.

The app works without the key: the assistant returns 501 and the UI answers locally.

## Language

English and French share one typed dictionary (`src/i18n/en.ts` is the source of truth;
`fr.ts` is `Record<TranslationKey, string>`, so a missing translation is a compile error).
The chosen language persists in `localStorage` under `floodsight.lang`; first visit follows
the browser, defaulting to English.

## Layout notes

- Desktop: fixed 380 px side navigation, content column max 1080 px.
- Mobile: fixed top bar + bottom tab bar, safe-area padding, 44 px touch targets.
- Compare slider uses two Leaflet panes and CSS `clip-path` over one map, so panning/zoom stay
  in sync by construction.
- Map overlays are `ImageOverlay`s pinned to `stats.bounds`; the flood layer swaps by date key.
